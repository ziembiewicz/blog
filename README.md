# blog@devops — Hugo + "phosphor" theme

A technical blog / DevOps portfolio site styled as a green phosphor terminal (with an ember accent). Static site generated by **Hugo**, published automatically via **GitHub Actions** to **GitHub Pages**.

---

## 1. How it was built

1. HTML mockup — three directions (pixel CRT, mainframe 3270, "modern phosphor"); modern phosphor with the ember accent was chosen.
2. The approved layout was ported 1:1 into a Hugo theme: the frame (topbar + 3 columns), post cards, right column (recently added, trending tags, client detected), footer.
3. Colors and glow are kept in CSS variables (`:root` dark, `html[data-theme="light"]` light). Fonts: JetBrains Mono (UI), IBM Plex Mono (body), Space Grotesk (tagline).
4. The theme ships no content — posts, author details and links go into `hugo.toml` and `content/`.

Stack: Hugo (extended) · GitHub Actions · GitHub Pages · Google Fonts · api.ipify.org (client IP, optional).

## 3. Local setup

### Requirements
- **Hugo extended** ≥ 0.128 (`hugo version` must include `extended`)
- Git
- VS Code (recommended extensions: *Hugo Language and Syntax Support*, *Markdown All in One*, *Front Matter CMS*)

### Installing Hugo
- Windows: `winget install Hugo.Hugo.Extended` or `choco install hugo-extended`
- macOS: `brew install hugo`
- Linux: `sudo snap install hugo` or the `.deb` package from https://github.com/gohugoio/hugo/releases (the `hugo_extended_*` variant)

### Running
```bash
unzip hugo-blog.zip && cd hugo-blog
hugo server -D          # -D also shows drafts
# → http://localhost:1313  (live reload on every save)
```

## 4. Configuration

### 4.1 `hugo.toml` — the `[params]` section
| Key | What it sets |
|---|---|
| `baseURL` | production address, e.g. `https://USER.github.io/` or your own domain with a trailing `/` |
| `title` | site title (title bar, RSS) |
| `prompt` | prompt text in the topbar (`blog@devops:~$ >`) |
| `author`, `tagline` | full name, description under the photo |
| `avatar` | path to the photo, `/img/avatar.jpg` by default |
| `footerLine`, `stack` | left/right part of the footer (`{year}` = current year) |
| `totalRowsLabel` | counter format `ROW {from} TO {to} OF {total}` |
| `clientDetected` | `true/false` — the CLIENT DETECTED section |
| `ipEndpoint` | API returning `{ "ip": "..." }`; empty string = no IP |
| `recentCount`, `trendingCount` | how many entries in "recently added" / "trending tags" |
| `[params.social]` | `github`, `x`, `facebook`, `email` (mailto:) — empty = the icon disappears |

### 4.2 The `[menu]` section
Every item has `name`, `url`, `weight` (order) and `params.icon` (the character in the small square). Add/remove `[[menu.main]]` as needed.

### 4.3 Photo and covers
- `static/img/avatar.jpg` — square, min. 400×400 (displayed in a 140 px circle).
- `static/img/posts/<slug>.jpg` — 1600×900 covers; in front matter: `cover: /img/posts/<slug>.jpg`. No cover = a striped placeholder.

Covers can be pulled from Unsplash automatically — see 4.8.

### 4.4 New post
```bash
hugo new posts/my-post.md
```
Front matter (from `archetypes/posts.md`):
```yaml
title: "Title"
date: 2026-09-08T10:00:00+02:00
draft: true          # set to false before publishing
categories: ["Kubernetes"]   # the first one = [ CATEGORY ] on the card
tags: ["gitops", "argocd"]
cover: "/img/posts/my-post.jpg"
description: "Lead — 1-2 sentences shown in the listing"
```
Body in Markdown; code blocks with highlighting (` ```yaml `), tables, quotes, images — all styled by the theme.

### 4.5 The "About" / "Archive" pages
- `content/about.md` — any Markdown, `layout: about`.
- `content/archive/_index.md` — generated automatically, nothing to add.
- Hugo builds categories and tags itself from front matter (`/categories/`, `/tags/`).

### 4.6 Colors / theme
All colors live in `themes/phosphor/assets/css/main.css` under `:root` (dark) and `html[data-theme="light"]`. Changing `--accent` switches the whole ember accent. Scanlines: remove `<div class="scanlines">` from `baseof.html` or set `.scanlines{display:none}`.

### 4.7 Custom domain (optional)

**No `CNAME` file is needed.** That is the branch-based publishing flow; with the GitHub Actions
deployment used here, GitHub creates no `CNAME` file and ignores one if it exists.

**Order matters.** Add the domain in GitHub *first*, then create the DNS record. Pointing DNS at
GitHub before claiming the domain in repository settings leaves a window in which someone else
can host their site on your subdomain.

1. Settings → Pages → Custom domain → `blog.yourdomain.com` → Save.
2. Create the DNS record at your registrar:
   - **subdomain** (`blog.yourdomain.com`) — one record:
     `CNAME blog → USER.github.io` (the account, without the repository name)
   - **apex** (`yourdomain.com`) — four A records:
     `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
3. Set `baseURL = "https://blog.yourdomain.com/"` in `hugo.toml`. CI overrides this from
   `actions/configure-pages`, so it mainly affects local production builds — but keep it correct.
4. Once GitHub finishes its DNS check, tick **Enforce HTTPS**. It can take up to 24 hours to
   become available.

### 4.8 Unsplash covers

`scripts/Get-UnsplashCover.ps1` searches Unsplash, downloads a cover into
`static/img/posts/<slug>.jpg` and writes the attribution fields into the post's front matter.

**Deliberately an authoring-time step, not a build step.** The Unsplash API is never called
during `hugo build`, so CI needs no secret, the deploy has no external dependency, and a demo
app's 50 requests/hour cannot break a build. Images are committed alongside the post.

#### Credentials
Only the **Access Key** is needed. The **Secret Key** is for OAuth (acting on behalf of a
logged-in Unsplash user) and this project never does that — do not put it in the repo.

```powershell
copy .env.example .env      # then paste the Access Key into .env  (git-ignored)
# or, for one session only:
$env:UNSPLASH_ACCESS_KEY = 'your-access-key'
```

#### Usage
```powershell
# 1. see the candidates without downloading anything
./scripts/Get-UnsplashCover.ps1 -Post Hello -Query "kubernetes" -List

# 2. take one of them
./scripts/Get-UnsplashCover.ps1 -Post Hello -Query "kubernetes" -Index 3
```

| Parameter | Default | Meaning |
|---|---|---|
| `-Post` | — | slug, filename or path of the post |
| `-Query` | — | search phrase |
| `-Orientation` | `landscape` | `landscape` / `portrait` / `squarish` |
| `-Index` | `1` | which search result to use |
| `-List` | off | print candidates and exit, downloading nothing |
| `-Width`, `-Height` | `1600`, `900` | output size (centre-cropped by entropy) |
| `-Quality` | `80` | JPEG quality |
| `-AppName` | `blog-devops` | `utm_source` in attribution links |

The script writes four front matter keys — `cover`, `coverAlt`, `coverCredit`, `coverCreditUrl` —
and re-running it overwrites them in place rather than duplicating.

#### Attribution
Per the Unsplash API Guidelines, the script calls the `download_location` endpoint on every
download (their download counter), and `single.html` renders a credit line under the cover:
*Photo by \<photographer\> on Unsplash*, both links carrying `utm_source` / `utm_medium`.
Set `unsplashApp` in `hugo.toml` to your registered Unsplash application name.

## 5. Deploying to GitHub Pages (CI/CD)

1. Create a repo on GitHub (e.g. `USER.github.io` for the root address, or any `blog` → `USER.github.io/blog/`).
2. Locally:
   ```bash
   git init && git add . && git commit -m "init: hugo blog + phosphor theme"
   git branch -M main
   git remote add origin git@github.com:USER/REPO.git
   git push -u origin main
   ```
3. GitHub → **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. Every push to `main` triggers `deploy.yml`:
   - checkout → install Hugo extended (version in `HUGO_VERSION`) →
   - `hugo --gc --minify --baseURL <pages-url>` →
   - htmltest (internal links, non-blocking) →
   - upload artifact → `deploy-pages`.
5. Status in the **Actions** tab; the address in **Settings → Pages**.

Writing flow: VS Code → `hugo server -D` → when ready set `draft: false` → `git commit -m "post: ..."` → `git push` → the post is online in about a minute.

## 6. Testing

### Locally
- `hugo server -D` — preview with drafts and live reload.
- `hugo --gc --minify` — full build into `public/`; template errors surface here.
- `hugo --printPathWarnings --printUnusedTemplates` — warnings about paths / unused templates.
- Search: type a phrase in the topbar (⌘K / Ctrl+K focuses it, Esc closes). The index is `/index.json` — check `http://localhost:1313/index.json`.
- Light/dark mode: the toggle in the topbar; the choice is stored in `localStorage`.
- The "scroll to top" arrow: appears once the search field scrolls out of view (IntersectionObserver).
- CLIENT DETECTED: IP from `ipEndpoint`, the rest from `navigator`; shows `n/a` if the API is blocked.
- Responsive: narrow the window below 1100 px (right column moves underneath) and below 760 px (single column, cards without the left cover).

### Links
```bash
hugo --minify
curl -sSL https://github.com/wjdp/htmltest/releases/download/v0.17.0/htmltest_0.17.0_linux_amd64.tar.gz | tar xz htmltest
./htmltest -c .htmltest.yml
```
(Windows: download the binary from the htmltest releases.) Set `CheckExternal: true` in `.htmltest.yml` to check external links too.

### In CI
- Build fails → the Actions tab → the **Build** step log (Go template errors point at the file and line).
- Lighthouse (optional): add a `treosh/lighthouse-ci-action` step after the build.

### Checklist before the first public push
- [ ] `baseURL`, `title`, `author`, `tagline`, social in `hugo.toml`
- [ ] `static/img/avatar.jpg`
- [ ] `content/posts/sample-post.md` removed or replaced
- [ ] `hugo --gc --minify` passes locally without errors

## 7. Known limitations
- Search runs client-side (fetching `index.json`) — fine for a few hundred posts; swap it for Pagefind at a larger scale.
- The client IP requires an external API (Pages is static hosting); disable `clientDetected` if you do not want the dependency.
- Comments are not built in — the simplest option is to add giscus (GitHub Discussions) in `single.html`.
